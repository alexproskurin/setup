# claude-mods

Personal **mods** for coding-agent harnesses: **Claude Code, Codex and opencode**. Each mod is **written once, in Claude Code's format**. `install.sh` installs it into Claude Code as-is and **generates** the Codex and opencode versions. This folder lives inside the `setup` git repo (`~/Documents/workBrain/Personal/setup`), not at its root. Paths below are relative to `claude-mods/`. `CLAUDE.md` just imports this file.

## What you write (the single source of truth)

```
.claude-plugin/marketplace.json        one entry per mod (scripts/new-mod.sh adds it)
mods/<mod>/
  .claude-plugin/plugin.json           name (== folder), version, description, author
  skills/<skill>/SKILL.md              THE DEFINITION: a Claude Code skill whose !`…` lines run the code
  skills/<skill>/scripts/<file>        THE CODE: any language (TypeScript via bun is fine), chmod +x
build/                                 GENERATED by install.sh for Codex/opencode. Gitignored; never edit
```

A definition looks like this (`mods/my-mod/skills/hello/SKILL.md`):

```markdown
---
name: hello
description: Say hello from a script. Use when the user asks to say hello or to test that mods work.
argument-hint: "[name]"
allowed-tools: Bash(${CLAUDE_SKILL_DIR}/scripts/hello.ts *)
---

!`${CLAUDE_SKILL_DIR}/scripts/hello.ts $ARGUMENTS`

Reply with the output above exactly as printed, and nothing else.
```

### Rules that keep a definition portable

**Frontmatter**
- `name` must equal the folder name and be kebab-case. `description` is required; quote it if it contains `:` or quotes.
- Every `` !`…` `` command needs an `allowed-tools: Bash(<command> *)` entry, or Claude Code aborts the skill.
- Other Claude fields (`argument-hint`, `model`, …) work in Claude and are dropped from the generated files.

**Running code**
- Use **inline `` !`…` ``** lines, with `!` at the start of a line or after a space.
- Claude's ```` ```! ```` fenced blocks are not translated; `install.sh` warns about them.

**Paths**
- `${CLAUDE_SKILL_DIR}` and `${CLAUDE_PLUGIN_ROOT}` become absolute paths in the generated files.
- `${CLAUDE_PROJECT_DIR}` becomes `.`.

**Arguments**
- Prefer **`$ARGUMENTS`**, and have scripts **join** their args (`"$*"`, `process.argv.slice(2).join(' ')`). Verified on `Sam Smith`:
  - Claude Code word-splits it: `[Sam][Smith]`.
  - opencode passes one argument: `[Sam Smith]`.
- Claude's positional `$0`, `$1` (0-based) are renumbered to opencode's `$1`, `$2`, but opencode then appends the leftover words. Avoid positional arguments unless you need them.
- Named `arguments:` are Claude-only, and `install.sh` warns about them.

**Scripts**
- A shebang plus `chmod +x`. Output should stand on its own: every harness just shows it.

**Names**
- Skill names must be unique across mods, because Codex and opencode share `~/.agents/skills`.

## How each harness gets it (verified 2026-10-13: Claude Code 2.1.296, Codex 0.154, opencode 1.18.31)

| | Claude Code | Codex | opencode |
|---|---|---|---|
| Installed as | the mod as a plugin, read in place | `build/agents/skills/<skill>` linked into `~/.agents/skills` | the same `~/.agents/skills` link, plus `build/opencode/commands/<skill>.md` linked into `~/.config/opencode/commands` |
| `` !`…` `` lines | run before the model sees the skill | rewritten as "**Run:** `cmd`"; the model runs them | the command runs them before the model; the skill tool gets the "Run:" version |
| Invoke | `/my-mod:hello` | `$hello` or the `/skills` picker | `/hello` |
| After editing | script: nothing; SKILL.md: `/reload-plugins` | script: nothing; SKILL.md: re-run `./install.sh` | same as Codex |
| Context file | `CLAUDE.md` (imports this) | `AGENTS.md` | `AGENTS.md` |

**Model turns:** a model turn follows in all three. The `` !`…` `` output becomes part of the prompt and the model relays it. Only Claude Code can skip the model entirely, using function hooks (see "Claude-only extras").

**Safety** (verified):
- **Claude Code:** checks `` !`…` `` against your permission rules. `/x a; touch f` and an unbalanced `it's` both abort and do not run.
- **opencode 1.18:** shell-quotes `$ARGUMENTS`, so injection attempts arrive as plain text. Its `` !`…` `` runs outside its permission system. The v2 docs warn that arguments are expanded into shell blocks, so **re-check this after upgrading to opencode 2**.
- **Codex:** the model runs the command under Codex's sandbox and approval rules.

## Workflow

1. `scripts/new-mod.sh [--ts] <name> "description"` writes the definition and a starter script (bash, or TypeScript with `--ts`), and lists the mod in the marketplace.
2. Edit the script and `SKILL.md`. Run the script directly to test it.
3. `./install.sh <name>`. It checks, then generates, then installs. The checks:
   - name, description and kebab-case;
   - every `` !`…` `` path exists and is executable;
   - warnings for missing `allowed-tools` and for Claude-only syntax;
   - unique skill names;
   - `claude plugin validate`, and `claude plugin test` if the mod has tests.
4. `./install.sh --list` shows what is installed where.
   - `-H claude,codex,opencode` limits the harnesses.
   - `--uninstall` removes a mod. It keeps the shared `~/.agents/skills` link while Codex or opencode still uses it.

### Testing without touching the real configs

```sh
export HOME=$(mktemp -d) CLAUDE_CONFIG_DIR=$(mktemp -d)   # isolates ~/.agents, ~/.codex, ~/.config/opencode, Claude
./install.sh
codex debug prompt-input hi | grep -- '- hello:'          # Codex: model-visible skill list, no model call
opencode debug skill > /tmp/s.json; jq -r '.[].name' /tmp/s.json   # opencode (redirect: piped output is truncated)
```

Running the `` !`…` `` lines for free, with no real model call:
- **Claude Code:** `claude -p --model claude-nonexistent --plugin-dir mods/<mod> "/<mod>:<skill> args" < /dev/null` renders the skill, which runs the `` !`…` `` lines, then fails on the model.
- **opencode:** put `"model": "fake-provider/fake-model"` in an isolated `opencode.json`, then run `opencode run --command <skill> "args"`. The first run in a fresh `HOME` can take over 90 seconds.

Codex may not be on PATH. `install.sh` also looks in `/Applications/ChatGPT.app/Contents/Resources/codex`, or you can set `CODEX_BIN`.

## Claude-only extras (optional)

Claude Code plugins can also hold function hooks (`hooks/hooks.json` + `register.ts`). Use them for things the other harnesses can't do: commands that skip the model, tool-call guards, panes. They are **not** generated for Codex or opencode.

**Before you start**
- Load the `plugin-authoring` skill first. Its generated `claude-code.d.ts` is the API reference (EARLY ACCESS: grep it, don't rely on memory).

**Writing the module**
- No Node or DOM; everything goes through `$`.
- To run a mod's script, call `$.process.run([`${$.plugin.root}/skills/<skill>/scripts/<file>`, ...])`.
- `$.process` and `$.fs` **bypass Claude's permission rules**.
- Guards must end with `.catch(($, e, next) => next.called ? next(e) : { deny: 'why' })`.

**Testing it**
- Tests import from `'claude-code/testing'`.
- A stub for a `$`-call event returns `{ value: … }`.
- `$.command.run` in a test needs `origin: { kind: 'composer' }` and `presentation: { isFullscreen: false, columns: 120 }`.
- `install.sh` runs `claude plugin test` for any mod that has `hooks/*.test.ts`.

## Not built yet

- **A no-model Claude command generated from the same SKILL.md:** an opt-in function hook that runs the `` !`…` `` lines and prints their output.
- **Portable guards:**
  - Claude Code and Codex share the classic command-hook format (`PreToolUse` and others, JSON on stdin, exit 2 to block).
  - opencode 1.x needs a TS plugin whose `tool.execute.before` throws.
- **opencode 2:** server plugins can add commands with an `execute()` function (`ctx.command.transform`). That might allow no-model commands there.

## Sharing

`.claude-plugin/marketplace.json` must sit at the root of a git repo for `/plugin install <mod> --marketplace <owner>/<repo>`, so publish `claude-mods/` as its own repo first. Codex and opencode users would run `install.sh`.
