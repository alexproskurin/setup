# claude-mods

Personal Claude Code **mods**: function-hook plugins whose TypeScript runs inside Claude Code (slash commands that execute code, tool-call guards, status lines, panes, etc.). Each mod is its own plugin under `mods/`. This folder is a plugin marketplace named `claude-mods` that lists them.

This folder lives inside the `setup` git repo (`~/Documents/workBrain/Personal/setup`), not at its root. Paths below are relative to `claude-mods/`; run the scripts from here or by full path (they resolve their own location).

## Before writing or changing a mod

Load the `plugin-authoring` skill first. When it loads, it writes this Claude Code build's API declarations (`claude-code.d.ts`, about 14k lines) and example mods. **Those types are the reference.** Grep them for the event or `$` method you need (`'command.run'`, `process: {`, `export type ToolCallResult`) and read the declaration. Don't rely on memory: the API is marked EARLY ACCESS and changes between releases.

## Layout

```
.claude-plugin/marketplace.json   marketplace "claude-mods"; one entry per mod, source ./mods/<name>
mods/<name>/
  .claude-plugin/plugin.json      name (== folder name == marketplace entry), version, description, author
  .claude-plugin/types/           GENERATED by Claude Code on load; gitignored, never edit or commit
  hooks/hooks.json                { "modules": ["./register.ts"] }
  hooks/register.ts               export const register: Register = (on, options) => { ... }
  hooks/*.test.ts                 run by `claude plugin test mods/<name>`
  types/index.d.ts                only if the mod keeps $.state values (named in plugin.json "types")
install.sh                        validate + test + install mods into Claude Code (see --help)
scripts/new-mod.sh <name> "desc"  scaffold a mod and add it to marketplace.json
```

## Workflow

1. `scripts/new-mod.sh <name> "description"`: creates `mods/<name>/` and lists it in `marketplace.json`. If you create a mod by hand, add its marketplace entry too. `install.sh` warns about unlisted folders.
2. Write `hooks/register.ts` and at least one `hooks/*.test.ts` for each behaviour asked for.
3. `claude plugin validate mods/<name>` and `claude plugin test mods/<name>` must both pass. Also run `claude plugin validate .` after touching `marketplace.json`.
4. Try it live: `claude --plugin-dir mods/<name>` (hot-reloads on save; add `--debug` to see skipped hooks).
5. `./install.sh [<name>...]` installs at user scope. Installed mods are read **in place** from `mods/<name>`, so after an edit, `/reload-plugins` in a session is enough. No reinstall and no version bump are needed locally.

To test `install.sh` without touching the real Claude config: `CLAUDE_CONFIG_DIR=$(mktemp -d) ./install.sh`.

## Mod rules (the engine enforces these)

- The hooks module is an ES module (`.ts`, `.tsx`, `.js`, `.mjs` and similar). It has **no Node, no DOM, no `require`, no dynamic `import()`**. Everything outside the module goes through `$`: `$.process.run(argv)`, `$.fs`, `$.http.fetch`, `$.tool.call`, `$.ui.*`, `$.store`/`$.state`.
- `on(event, matcher?, hook)`. A hook is `($, e, next)`:
  - returning without calling `next` answers for itself;
  - `next({ ...e, x })` rewrites what the rest of the chain sees;
  - `await next(e)` runs the engine's own behaviour first.
- **Slash command:** call `$.command.register({ name, description })` inside `session.start` (then `return next(e)`), and add a `command.run` hook with matcher `{ command: name }` that returns `{ text }`. It can also return:
  - `context: string[]`: text the model sees and the user doesn't;
  - `exitCode`: the process exit code under `claude -p`.
  Never reuse a built-in command name.
- **Guards** (hooks that deny something) must end with `.catch(($, e, next) => next.called ? next(e) : { deny: 'why' })`. Otherwise a guard that throws is skipped and the call goes through.
- Other code in your languages (Python, shell) belongs in the mod folder and is run with `$.process.run([...])`. `$.plugin.root` is the mod's folder. `$.process.run` takes argv with no shell, has a 30 s default timeout and returns `{ exitCode, stdout, stderr }`.
- `$.process`, `$.fs`: run as the OS user and **bypass Claude's permission rules and prompts**.
- `$.tool.call(...)`: goes through the allow/deny rules and the permission dialog. Use it when an action should respect the user's permission settings.
- Do not write a mod that quietly works around the user's deny rules.

## Testing gotchas (verified here)

- Import from `'claude-code/testing'`: `test(name, async ($, on) => { ... })`, plus `expect`, `mock`, `describe`.
- The test environment has no fs, network or process. Hooks registered with the test's `on` sit beneath the plugin and stand in for the engine. Anything unanswered throws `no implementation for <event>`.
- A stub for a `$`-call event (`process.run`, `fs.read`, `http.fetch`, …) must return **`{ value: <result> }`** (or `{ deny }`), not the bare result:
  `on('process.run', () => ({ value: { exitCode: 0, stdout: 'x', stderr: '', isStdoutTruncated: false, isStderrTruncated: false } }))`
- In a test, `$.command.run` takes the full `CommandRunInput`. It type-checks only with
  `origin: { kind: 'composer' }` and `presentation: { isFullscreen: false, columns: 120 }`.
  See `mods/my-mod/hooks/register.test.ts`.

## Type-checking

Once an interactive session has loaded the mod (`--plugin-dir` or installed), `.claude-plugin/types/` and a generated `tsconfig.json` are written next to it. Then run `npx -p typescript tsc -p mods/<name>`.

Before that, use the tsconfig in the header of the skill's `claude-code.d.ts`. Keep that tsconfig **outside** `claude-mods/`, with `include` naming the skill's `claude-code.d.ts` and `mods/<name>/hooks`.

## Sharing

`/plugin install <name> --marketplace <owner>/<repo>` expects `.claude-plugin/marketplace.json` at the **GitHub repo's root**, and here it sits in `claude-mods/`. To share mods, either publish `claude-mods/` as its own repo, or add a root-level marketplace to `setup` whose sources are `./claude-mods/mods/<name>`. People who install from GitHub get a copy, not the folder, so bump `version` in `plugin.json` for each release (`claude plugin tag mods/<name>` creates the git tag).
